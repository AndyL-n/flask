# 烟厂地块演示 SQL

三个脚本的业务表均明确限定为 `jdf` 数据库。服务器库名不同，请替换各文件中所有作为数据库标识符的 `jdf`。

## 1. 回滚此前新增的辅助表

执行 `yanchang_schema_rollback.sql`，删除此前新增的五张 `_jdf_yanchang_*` 表。原业务表字段、索引和外键不作修改；业务数据保留。DDL 会立即提交，删除的辅助表备份无法用事务恢复。

你提供的结构显示五张辅助表索引基数为零，这不能保证表中没有数据。如旧版导入曾成功且需要恢复原配置，应先执行旧版配套回滚脚本，再清理辅助表；新版数据回滚不依赖这些表。

## 2. 导入演示数据

执行 `yanchang_site_import.sql`，直接向原有 `site`、`device`、`pole`、`device_record` 表写入数据，不创建普通表或临时表，不修改结构。

包含最新围栏、两台设备、八个杆子和 2026-09-15 至 2026-10-14 的 5,758 条模拟运行记录。当前在线待机、水位100%；A1 水平270°俯仰32°，B1 水平0°俯仰30°。

使用原有 `site.info` 字段保存演示标记 `烟厂地块模拟演示_20261014`。已有同名场地无此标记，或设备属于其他场地时，所有业务写入均跳过，末尾 `import_allowed=0`。请检查归属，不要直接将已有真实场地标为演示数据。

场地编号优先2000005；被其他场地占用时另分配编号，使用末尾 `imported_site_id` 访问大屏。重复导入跳过设备名和时间相同的日志，并重新同步当前模拟参数。

## 3. 回滚演示数据

执行 `yanchang_site_rollback.sql`。仅对有对应演示标记的烟厂地块，按设备名和精确时间清理本脚本的模拟日志，再清理八个演示杆子、两台演示设备和场地。

如果设备仍有时间清单以外的运行记录或其他杆子，保留设备；场地仍有关联设备、杆子、环境记录、访问权限、用户或单位时，保留场地并输出提示。这些额外数据不会自动删除。回滚可以重复执行。

两个数据脚本仅需原表查询、插入、更新、删除权限及支持事务的 InnoDB，不需要建表权限。结构清理脚本需要删除辅助表权限。

在 phpMyAdmin 中选择项目数据库，在“导入”页上传完整 SQL 文件。同一连接完整执行，不要使用 `--force`；遇错停止后续语句并执行 `ROLLBACK;`。SQL 不包含数据库密码、登录账号或新增访问权限。
